# Session Packet

## Segment
- ID: S167
- Deliverable(s): Governed MCP relay v0
- Date: 2026-08-27

## Objective
- Primary objective: replace the “no upstream invocation” gap with one narrowly governed remote MCP tool call whose authority, cost, outcome, and replay behavior are durable and independently verifiable.
- Success criteria: an operator attests to and imports one exact auth-none, server-declared read-only/idempotent tool; an agent-bound principal invokes it once under fresh capability and policy checks; crash ambiguity never replays; revocation denies the next attempt before network; every outcome receives an Ed25519 receipt.

## Dependencies
- S163 authenticated, idempotent, single-process containment baseline.
- S164 official MCP Streamable HTTP interoperability and inbound discovery gateway.
- S165 durable capability-token roots and generation-aware revocation.
- S166 product-truth and unsafe-surface containment.

## Scope
### In Scope
- Official `mcp==2.1.1` client and Streamable HTTP transport in the application runtime.
- Exactly one operator-configured target; no request-supplied endpoint.
- `auth: none`, explicit operator read-only attestation, and server-declared read-only/non-destructive/idempotent annotations; no claim that annotations enforce upstream behavior.
- Imported server identity, protocol version, input/output schemas, annotations, and full contract digest.
- Agent credential, JWT, or delegation principal with `relay.call`; exact capability audience/resource/subject/tool scope.
- Last-moment revocation-aware authority/policy check under a shared local fence.
- Owner/tenant/capability budget authority with 80/100/120 thresholds.
- Durable domain idempotency, pending/succeeded/failed/indeterminate states, and no automatic retry.
- Ed25519 receipts, public JWK, configured-authority API verifier, and explicit-key offline CLI verifier.
- Separate-process official MCP proof plus crash-after-result and next-call revocation proof.

### Out of Scope
- Write or destructive tools, upstream authentication, secrets, OAuth, arbitrary target routing, or more than one target.
- A2A task transport, approval pause/resume, marketplace settlement, webhook delivery, or managed runtime.
- PostgreSQL, Redis, Alembic, transactional outbox, multiple workers/replicas, or distributed locks.
- OpenTelemetry, production hosting, customer onboarding UI, human login, pilot, ROI, or customer outcome.

## Assumptions
- Operator-owned exact configuration is the only routing authority; callers cannot choose or alter a URL.
- Ambiguous completion is more dangerous than a missed retry, so any post-dispatch uncertainty is terminal `indeterminate`.
- SQLite and the local authority fence provide one-process ordering only and are not distributed-safety evidence.

## Implementation Plan
1. Pin the official MCP client in the production runtime and validate one exact operator target.
2. Import and persist the complete safe tool contract.
3. Add default-deny relay policy and last-moment authority checks.
4. Add atomic budget reservation, domain idempotency, outcome state, and recovery.
5. Add Ed25519 receipts and public/offline verification.
6. Expose thin import, budget, enable/disable, call, status, receipt, key, and verifier APIs.
7. Prove the complete journey against an official MCP server in a separate process.
8. Run static, full, package, audit, browser, image, DOCX, and independent exact-head gates.

## Verification Plan
- Contract: reject malformed target config, URL ambiguity, auth modes, unsafe annotations, schema drift, malformed input, malformed output, and output over 64 KiB.
- Security: reject API-key callers at the relay, wrong tenant/subject/audience/resource/scope, revoked authority, disabled target, and cross-owner reads.
- Reliability: one call only, no redirects/retries, permanent idempotency conflict detection, crash recovery to indeterminate, no replay.
- Cost: atomic owner/tenant/capability budget at 80% soft alert, 100% reauthorization, and 120% hard stop.
- Evidence: canonical Ed25519 receipt round trip, tamper rejection, public API verification, and offline CLI verification.

## Acceptance Criteria
1. No relay request field can select an endpoint or tool outside the exact operator allowlist.
2. Only one auth-none tool with explicit operator attestation and server-declared read-only, non-destructive, and idempotent annotations can be imported.
3. A fresh agent principal and capability are checked immediately before `network_started_at` is persisted.
4. Every dispatched call is attempted exactly once; ambiguous completion is never retried.
5. Revocation before dispatch results in zero upstream calls and released budget.
6. Revocation after one success denies the next attempt before a second upstream call.
7. Crash after remote result recovers to a signed indeterminate receipt and same-key replay remains blocked.
8. All outcome receipts verify with public material only and tampering fails closed.
9. Full local and proportional artifact gates pass with zero admitted HIGH/MEDIUM exact-head findings.
10. Public copy retains the global NO-GO verdict and names all excluded remote/deployment/customer capabilities.
