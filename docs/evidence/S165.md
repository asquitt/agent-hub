## Implemented Outcomes
- Replaced process-memory capability-token, DID, and VC authority with additive SQLite identity migrations and canonical identity-storage transactions.
- Persisted immutable owner, tenant, issuer, subject, resource, audience, expiry, and identity-generation snapshots for authority artifacts.
- Added version-2, domain-separated capability token signing; legacy version-1 tokens fail closed.
- Required active same-boundary issuer and subject identities, actor scope authority, and agent-bound self authority at issuance.
- Required exact persisted audience and resource verification context and derived source IP from the HTTP peer rather than request JSON.
- Added tenant-scoped capability root get/list/revoke endpoints; responses never return reconstructable bearer token material.
- Made DID deactivation monotonic and durable while preserving stable DID continuity across legitimate identity-generation recovery.
- Bound VC issuer, subject, proof payload, and `credentialSubject.id`; reserved claims cannot overwrite authority fields.
- Made explicit capability/VC revocation and agent-revocation cascade durable and immediately effective.
- Rotated identity authentication generation on actual configuration-checksum changes while preserving idempotent same-checksum writes.
- Preserved recovery semantics: old tokens and VCs remain invalid after suspend/reactivate or reconfiguration, while newly issued VCs can use the stable active DID.
- Added owner-plus-tenant filtering and nondisclosing cross-boundary behavior for read, list, verify, revoke, resolve, and deactivate operations.
- Required idempotency keys for durable capability issuance, VC issuance, and capability revocation; same-key retries replay one persisted result.
- Normalized missing, foreign-boundary, forged, and agent-impersonation capability administration failures to stable nondisclosing 4xx responses.
