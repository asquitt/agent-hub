# S167 Evidence: Governed MCP Relay v0

## Status

Implementation, local verification, browser proof, and documentation rendering are complete. Exact-candidate image, independent review, PR merge, and post-merge verification remain pending.

## Implemented Outcomes

- Added one exact operator-configured MCP target with no request-supplied URL, HTTPS by default, and loopback HTTP only under an exact development opt-in.
- Requires `operator_attests_read_only: true` and server-declared read-only/non-destructive/idempotent annotations. MCP annotations are treated as untrusted hints, not technical prevention of upstream side effects.
- Added the official MCP 2.1.1 client to the production runtime with redirects and retries disabled.
- Imports one operator-attested, server-declared read-only, non-destructive, idempotent auth-none tool and persists its server/protocol identity, strict schemas, annotations, and full contract digest.
- Requires an agent-bound revocation-aware principal plus exact relay scope and persisted capability-token authority.
- Repeats principal, capability, target, and policy verification under a shared local authority fence immediately before recording network dispatch.
- Persists domain idempotency and pending, succeeded, failed, or indeterminate outcomes; no dispatched or ambiguous call is automatically retried.
- Atomically reserves admin-controlled owner/tenant/capability budgets with 80% soft alert, 100% reauthorization, and 120% hard stop behavior; non-finite limits fail at API and storage boundaries.
- Signs every final outcome with Ed25519. The API verifier resolves AgentHub's configured key rather than accepting caller-selected key material; public JWK and explicit-key offline verification remain available.
- Reconciles abandoned pre-dispatch work to failed and dispatched work to indeterminate only after singleton ownership. Receiptless terminal recovery is restart-idempotent.
- Persists the immutable final target snapshot with `network_started_at`; recovery cannot attribute a call to a later reimported target.
- Fresh server identity, protocol version, and tool contract are compared before `tools/call`. Connect/discovery failures are definite, uncharged, and recorded with no observed remote result.

## Evidence Boundaries

- One target and one operator-attested, server-declared read-only/idempotent auth-none tool are proven. Technical prevention of upstream side effects, upstream authentication, write tools, multiple targets, arbitrary routing, and generalized remote agents are not.
- The authority fence, budget transaction, recovery, and durable state are single-process SQLite behavior. PostgreSQL, Redis, multiple workers/replicas, failover, and distributed consistency are not implemented or claimed.
- No automatic upstream retry occurs. Indeterminate means the remote side effect cannot be proven and manual investigation is required.
- No hosted CI, public endpoint, provider deployment, human login, customer onboarding, pilot, ROI, or customer outcome is proven.
- Automatic GitHub Actions remain disabled and no workflow run is represented as green.
